# 32-bit Mac programs (m32)

macOS stopped running i386 Mach-O programs in Catalina, and Rosetta never ran
them. m32 runs them under AArchX: an executable with an i386 slice and no
x86_64 one is handed to `m32_run` instead of being refused, and runs in native
mode against the Mac's own arm64 frameworks.

```sh
make apis32                                   # i386 API databases from your SDK, into runtime/apis32
tools/fetch_guest32_cxx.sh                    # only for programs built with GCC's libstdc++
./ocerz -native "Some Game.app/Contents/MacOS/Some Game"
```

## What runs

Batman: Arkham Asylum Game of the Year Edition (Feral, 2014; Unreal Engine 3,
Objective-C 1, tcmalloc, Bink, FMOD Ex, OpenGL through Feral's IndirectX)
plays its title screen, its menus with the mouse, and gameplay with keyboard,
mouse and sound in MacShack, where m32 comes from. On this tree its New Game
opening runs at about 31 frames a second on an M4 Max, bound by the render
thread: the i386 JIT has none of the speed work that brought MacShack's build
to 60 yet.

Two things such a game needs from outside AArchX. Valve ships no 32-bit
`steamclient`, so a game's own i386 `libsteam_api.dylib` cannot start Steam
and the game relaunches itself through `steam://` and quits; an i386 stand-in
for `libsteam_api` is needed in its place. And Feral games keep their settings
and key bindings in an XML registry their options dialog writes
(`~/Library/Application Support/Feral Interactive/<game>/Preferences Data`);
that dialog is a legacy WebView that draws nothing under m32, so the values
it would write (`GameOptionsDialogShouldShow` 0, `GameOptionsDialogShown` 1,
`UseGLSL` 1, `FullScreen` 0, and the bindings) have to be there already.

## How it works

- **The window.** The guest runs as i386 code in a flat 4 GB window
  (`ocerz_mem_init(0, 4 GB)`) and never holds a host address. Host objects
  reach it as 8-byte handle cells at 0xE0000000-0xF0000000; guest data with a
  host twin (CFSTR literals, CF-typed data it only takes the address of) as
  aliases (`src/m32_handle.c`).
- **Imports.** An import from a system library is an address in the dyldapi
  trap window, and `ocerz_dyldapi_dispatch` hands a 32-bit cpu's trap to
  `m32_trap`. Each export's two notations come from `runtime/apis32`, which
  `tools/sdkgen.sh --guest i386` writes by parsing the SDK headers as i386
  macOS 10.14 beside arm64. Guest-only classes: `s` a C string, `P` one pointer
  written back, `W`/`V` one long written back, `Q` data whose layouts differ,
  `T` a `dispatch_time_t`, converted between the Intel and Apple silicon clocks.
  The generic crossing is `src/m32_cross.c`; the calls no notation describes
  have hand-written specials (`m32_libsystem.c`, `m32_stdio.c`, `m32_thread.c`,
  `m32_cf.c`, `m32_dyld.c`, `m32_gl.c`, `m32_audio.c`, `m32_zlib.c`).
- **Images.** Guest dylibs load from `@executable_path`, `@loader_path`,
  `@rpath` and `runtime/guest32` (`OCERZ_GUEST32_ROOT`), with dyld info or
  classic relocations; weak symbols coalesce to the first definition in load
  order, as dyld does.
- **Heap.** A dlmalloc mspace in the window (`OCERZ_M32_HEAP_MB`, default
  1024, growing on demand) until the program registers a malloc zone of its
  own (tcmalloc in Batman); malloc then runs the guest's zone through
  generated i386 thunks, and free goes by who owns the pointer.
- **Objective-C 1.** Selectors, guest classes, proxies and paired host classes
  with twins, categories, `+load` and `+initialize`, sends converted by the
  i386 and host encodings (`<leaf>.objc32` beside each database), exceptions
  with guest frames, blocks both ways, and swizzling with host IMPs
  (`src/m32_objc*.c`, `src/m32_blocks.c`, `src/m32_catch.m`).
- **C++ exceptions.** A two-phase Itanium unwinder over the guest's
  `__eh_frame` with the guest's personality routine (`src/m32_unwind.c`).
- **Clocks.** `mach_absolute_time` counts nanoseconds with a 1/1 timebase and
  `UpTime` follows it, as on an Intel Mac; Bink times its movies with them.
- **Threads** are host threads with a 32-bit cpu attached, at user-interactive
  QoS: at the default, macOS sometimes leaves a game's render thread on the
  efficiency cores for good.

## Tests

`make check-m32` runs the 34 programs in `tests/m32` against their
`.expected` output; add `OCERZ_NOJIT=1` for the interpreter alone. The
programs are committed in `tests/m32/bin`, because linking i386 needs Xcode
26's `ld-classic` (CLT 27's linker dropped i386): `M32_REBUILD=1` rebuilds them
with `tests/m32/build.sh`, using `M32_DEVELOPER_DIR` (default
`/Applications/Xcode.app`). The SDK has no i386 libraries any more, so
`build.sh` links against stub `.tbd` files made from the SDK's own lists; they
stay in the untracked `tests/m32/sdk`. `cxx` and `cxxexc` need
`runtime/guest32` and are skipped without it. `tests/m32/dbcheck.sh` spot
checks a generated database.

## Switches

| Variable | Effect |
| --- | --- |
| `OCERZ_M32LOG=imports,calls,images,objc,throws,glstat` | imports as they resolve, every crossing, image loads, Objective-C sends, C++ throws, OpenGL calls and frames per 10 s |
| `OCERZ_M32_KEEP_GOING=1` | run with unresolved imports, which then return 0 |
| `OCERZ_M32_HEAP_MB=<n>` | the guest heap's first size |
| `OCERZ_M32_MUTE=1` | the CoreAudio render callback outputs silence |
| `OCERZ_GUEST32_ROOT=<dir>` | where guest system libraries are looked for, instead of `runtime/guest32` |

## Limits

`long double` calls have no notation and stay unresolved. OpenCL is not
bridged (`clCreateContextFromType` answers 0, and Batman does without it).
Signal handlers are recorded but not delivered.
